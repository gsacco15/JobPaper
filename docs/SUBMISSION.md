## Listing

**Name:** JobPaper

**Short description:** Estimates, change orders, and job reports as PDFs

**Description:**

> JobPaper turns a contractor's notes and photos into three documents: an estimate, a change order, or a daily/weekly job report. Say "write up an estimate for…", "put together a quote for…", "bid for a…", "price out a…", "change order for…", "the customer added…", "they want to add… to the job", "daily report for the … job", "job report from these photos", "end of day report", or "weekly update for the homeowner". The document opens as an editable panel: tap any line to change it, then Download PDF or Copy as text. Totals, markup, and sales tax are calculated from your business settings. Estimates are saved as files in the chat, so a change order can reference the original estimate and its total. Works for remodel, bathroom, kitchen, roof, fence, deck, drywall, paint, HVAC, plumbing, electrical, landscaping, concrete, flooring, and tile jobs.

## Tool annotations and justifications

| Tool | readOnlyHint | destructiveHint | openWorldHint | Justification |
| --- | --- | --- | --- | --- |
| `create_estimate` | true | false | false | Builds and returns an estimate document from the user's description. Writes nothing and contacts no outside system. The panel saves files only when the user acts. |
| `create_change_order` | true | false | false | Reads the referenced estimate file and returns a change order document. Doesn't modify the estimate or anything else. |
| `create_job_report` | true | false | false | Returns a report document built from the user's notes and the photos they attached. Never fetches images. |
| `open_jobpaper` | true | false | false | Opens the JobPaper panel from the sidebar or thread tab. No side effects. |
| `open_document_file` | true | false | false | Opens a saved JobPaper file in the viewer. No side effects. |
| `edit_logo` | true | false | false | Opens the logo picker from settings. |
| `get_settings` (app-only) | true | false | false | Reads the user's business settings for the panel. |
| `save_logo` (app-only) | false | false | false | Saves the logo the user picked to their own settings. Idempotent. Not visible to the model. |
| `settings.read` / `settings.update` | — | — | — | Structured settings tools generated by `@openai/mcp-extensions`. |

## Inputs (minimal by design)

- `create_estimate`: `job_description` (required), `line_items[]`, `client_name`, `job_address_text` (only if typed — never looked up), `notes`
- `create_change_order`: `estimate_file` (required), `change_description` (required), `added_items[]`, `removed_item_ids[]`, `schedule_impact_days`
- `create_job_report`: `job_name` (required), `period`, `notes` (required), `photos[]`, `crew_count`, `hours`, `weather_text`, `issues`, `next_steps`

No precise location, no conversation history, no "context" catch-all.

## Reviewer notes (paste into submission notes)

> ChatGPT can write an estimate as text. JobPaper adds what plain text can't:
> 1. **An editable document panel** that looks like the PDF the customer receives. Tap any line to change qty, unit, or price; swipe or long-press to delete (with undo); drag to reorder. Totals recompute instantly.
> 2. **Correct totals, every time.** The server computes subtotal, markup, tax, and total from the user's saved settings. The model never does the math, and after the user edits the panel, the model gets the current numbers through model context.
> 3. **A branded PDF made on the device** (logo, business name, phone, line-item table, totals, deposit, approval line), plus an SMS-friendly "Copy as text".
> 4. **File persistence and change-order linkage.** Every document is a small JSON file in the chat (`.est.json`, `.co.json`, `.rpt.json`). JobPaper registers a file viewer for those extensions. A change order reads the original estimate total from the file — never retyped — and shows the original total, added and removed lines, net change, new contract total, schedule impact, and its sequence number (CO-1, CO-2…).
> 5. **Saved business defaults** through structured plugin settings, including a logo uploader.
>
> Data: job text is processed and returned, never stored. Photos are only those the user attached, never fetched. The only stored data is the user's business settings, keyed by a hash of the anonymous user ID. Payment terms are labeled "editable sample terms — not legal advice" in the panel.
>
> Test prompts:
> - "Write up an estimate for a bathroom remodel for Pat Henderson: demo the tile and vanity, about 50 sq ft of new tile floor, tile the shower to the ceiling, new vanity and toilet."
> - Then: "The customer added a heated floor and a shower niche. Change order."
> - "End of day report for the Henderson job — 3 guys, 8 hours, finished demo, subfloor is dry, grout is backordered" (attach 2–4 photos).
